# Скелет-маг: проба полного набора анимаций

Дата: 2026-09-12. Создано встроенным ImageGen, без PixelLab и без API/CLI генерации.
Основа — понравившаяся пользователю статичная проба из `../UpdateTrial-20260909/`.
Она сохранена без изменений. Согласованный тип атаки: колдовство посохом;
снаряд и свечение — отдельные изображения.

**Статус: комплект для художественной оценки, не принятый игровой ассет.**
Все 69 кадров вырезаны и технически подготовлены. Автоматическая генерация
не сохранила рисунок и движение достаточно строго для бесшовного внедрения.

Его можно открыть обычным способом из папки. Встроенный браузер Codex заблокировал

## Оценка качества

- Ожидание: персонаж узнаваем, но на шве цикла меняются складки, рёбра и лицо.
  Ноги привязаны к общей линии земли, но сами стопы не идентичны между кадрами.
- Ходьба: основной слабый клип. Похожие фазы повторяются в обеих половинах,
  чередование ног недостаточно убедительное; голова и колени меняют форму.
- Атаки: подъём посоха и жест свободной руки читаются. Длина посоха и стойка
  всё ещё плавают. Сначала пробовали горизонтальное наведение — там посох
  превращался в короткую палочку, поэтому вариант заменён.
- Переходы между клипами требуют согласования: задний капюшон в атаке отличается
  от ожидания; размер/рисунок черепа в разных листах не полностью совпадает.
- Смерть: есть резкий распад и оседание костей; череп при отделении заметно
  меняет форму и размер, а итоговая куча детальнее исходного персонажа.
- Эффекты: пригодны как грубая проба. Мягкий ореол пришлось удалять порогом,
  из-за чего слабые лучи и края упрощены. В базовые кадры персонажа они не вшиты.

Нет утверждения о готовности для выпуска. Для следующего качественного шага
важнее исправить согласованность движения и переходы, чем добавить ещё ракурсы.

## Обработка и воспроизводимость

`Sources/` содержит все выбранные генерации и три отбракованных листа с причиной
в имени. Точные запросы находятся в `Prompts/`. Генератор не соблюдал требуемые
малые размеры: фактически получены 1536×1024 и 1774×887, с приблизительной сеткой.

`prepare_atlases.py` механически нарезает равные ячейки, делает медианную выборку
внутри пикселей, убирает magenta-фон, приводит к общей палитре и собирает атласы.
Эффекты фактически сгенерированы на чёрном фоне с ореолом; сохранены области
G≥115 и B≥105, затем сведены к четырём цветам кристалла.

Для персонажа используется один масштаб на весь клип, выбранный по высоте
первой позы (около 88 px). Кадры не растягиваются независимо. Применяются только
целочисленные сдвиги для линии земли и центра опоры; в ходьбе горизонтальная
привязка по капюшону предотвращает скачки из-за смены опорной ноги. При смерти
горизонтальное движение обломков сохраняется. Анатомия кодом не дорисовывалась.

Палитра — 19 цветов из статичного мастера, с отдельными группами кости/ткань/
дерево/кристалл/контур. Это предотвращает глобальную замену тёмного контура
бирюзой или деревянного посоха фиолетовым. Жёсткая конечная сетка и бинарная
прозрачность получены обработкой, а не гарантированно точной нативной генерацией.

`qa.json` хранит размеры, хеши источников, сдвиги, границы и уникальность кадров.
`verification.json` — итоговую проверку PNG/GIF. Проверено отсутствие обрезанных
непрозрачных пикселей, единство палитры, бинарный alpha и прозрачная пустая ячейка.
Каждый кадр просмотрен на контактных листах; это не проверка плавности в игре.

`build_viewer.py` заново собирает автономный HTML после обработки изображений.
Нужны Python, Pillow и NumPy. Исходники сохраняются; скрипты меняют только
производные файлы внутри этой папки.

## Возможное подключение к Unity после художественной правки

Ни один файл из `Assets/`, сцена, prefab, GUID или AnimationClip в этой задаче
не изменялся. Unity MCP для этого проекта недоступен в текущем наборе инструментов;
импорт, Console, Play Mode и Game View не проверялись.

`manifest.json` описывает прямоугольники кадров в координатах от верхнего левого
угла, длительность, повтор и pivot (0.5, 0.5). Для Unity координату Y надо перевести
в отсчёт снизу. PPU необходимо взять у текущего врага при импорте; фильтр Point,
mipmaps выключены, alpha включён, компрессия без потерь пикселей.

Ожидаемое сопоставление: idle-side → Idle, walk-side → Run, cast-side → Hit,
cast-front → Hit_down, cast-back → Hit_up. Эти имена сами по себе не добавляют
дальнобойную механику: текущий EnemyAttackSystem использует существующий цикл
урона врага. Для мага потребуется отдельное подключение снаряда и события атаки.
Смерть предполагается отдельным эффектом, по схеме существующего скелета.

Предложенная точка выпуска — кадр с индексом 4 (пятый); это предложение,
не уже установленное событие. `staff_crystal_center_px` оценён по пикселям
кристалла каждого кадра для наложения отдельной вспышки. HTML показывает лишь
пример такого наложения. В GIF одноразовые клипы повторяются с 900 мс удержанием
финального кадра для удобства сравнения; в manifest указано игровое время кадров.
